# タイムスタンプ帯の位置を測る（mints の A3と、TreeeS が未確認。A4横は数値が未確認）

mints に提出すると、各ファイルの1ページ目に、裁判所がタイムスタンプの帯を付けます。多くは**ページの上部**に付きます。
LegalLeaves は、証拠番号をこの帯と重ならない位置に押します。ただ、帯の位置を実際に測れているのは **mints の A4縦だけ**です。
**TreeeS では、帯が付くかどうかも含めて、まだ分かっていません。**
ほかの用紙での位置や、TreeeS での扱いが分かれば、番号の位置と「帯と重なりそう」という知らせを正しく直せます。

測る機会のある方に、協力をお願いするための文書です。

## いまの状況

| システム | 用紙 | 帯の位置 | 状態 |
| --- | --- | --- | --- |
| mints | **A4縦** | 上端から **8〜19mm**、左端から **31mm** 〜 右端から **11mm**、**1ページ目のみ** | ✅ 実測済み |
| mints | A4横 | **右端に、縦に長く付く**（紙を左へ 90 度回して縦長にして見ると、A4縦と同じく上端に帯がある形）。この見立てどおりなら、右端から 8〜19mm、上端から 31mm 〜 下端から 11mm | △ 実際の提出で見た（2026-11）。**数値は測っていない**（A4縦からの換算） |
| mints | A3縦 | 不明 | ❌ 未確認 |
| mints | A3横 | 不明 | ❌ 未確認 |
| TreeeS | すべて | 帯が付くかどうかも不明 | ❌ 未確認 |

**A4縦の値を、そのままほかの用紙に当てはめることはできません。** 考えられるのは

- (a) 用紙の向きや大きさに関わらず、紙の上端から**同じ長さの位置**（8〜19mm）
- (b) 用紙の大きさに**比例した位置**
- (c) そのどちらでもない

のいずれかで、どれかは実際に提出してみないと分かりません。

## 測るのに必要なもの

1. **提出前**の PDF（LegalLeaves が作ったもの）
2. **提出後**の PDF（mints や TreeeS からダウンロードした、提出後の状態のもの）

TreeeS で提出した場合は、**帯が付いていたかどうか**だけでも助かります。

同じファイルの前後をそろえることが大事です（別のファイルどうしでは比べられません）。

> **PDF そのものは、どこにも送らないでください。** 提出した書類には、依頼者の情報や事件番号が入っています。
> 必要なのは下の「教えてほしい項目」の**数値だけ**です。

## 測り方

### 方法A: PDF を見るソフトの計測機能で測る（どなたでも）

Adobe Acrobat などの「ものさし」「計測」の機能で、紙の上端から帯の上端・下端までの長さを測ります。
画面の拡大・縮小に左右されないよう、**mm で表示される計測機能**を使ってください。

### 方法B: 付属の道具で測る（Node.js を使える方向け）

このリポジトリをダウンロードしたフォルダで、次を実行します（Node.js と、`npm install` で入る部品が必要です）。

```bash
node tools/measure-timestamp-band.js "提出前.pdf" "提出後.pdf"
```

2つの PDF を重ねて**違いが出た場所＝帯**を見つけ、位置を mm で表示します。
**ファイルはどこにも送信されません。** 表示されるのは数値だけです。

## 教えてほしい項目

用紙ごとに、次の6つが分かれば十分です。[Issues](https://github.com/lapi-clerk/LegalLeaves/issues) に書いてください。

1. **システム**（mints か TreeeS か）
2. **用紙**（A4横・A3縦・A3横のどれか）
3. 紙の**上端から帯の上端**まで（mm）と、紙の**上端から帯の下端**まで（mm）
4. 紙の**左端から帯の左端**まで（mm）と、**右端から帯の右端**まで（mm）
5. 帯が付いたのは**1ページ目だけ**か（2ページ目以降にも付いていないか）。TreeeS では、帯が付いたかどうか
6. 提出した**年月**（システムの変更で位置が変わることがあるため）

> 帯の中の文字（事件番号や当事者名）は**不要**です。Issues は誰でも見られるので、書かないでください。
> 画面の写真を載せる場合も、帯の中の文字や書類の中身が写らないようにしてください。

## 数値が届いたらやること（開発者向け）

1. **帯の位置の定義**を、用紙・システムごとの実測値に合わせて直す。定義は次の2か所にあり、**必ず同じ値にする**
   （画面と出力の両方で使うため）。
   - `src/timestamp-zone.js` の `TIMESTAMP_ZONE`・`STAMP_SAFE_Y`（画面の帯の表示・「帯と重なりそう」の判定・番号の既定の位置）
   - `py/legalleaves/pdf_engine.py` の `STAMP_SAFE_Y`（出力する PDF の番号の位置）
2. 帯が (a) の「上端から同じ長さ」だった場合は、番号の位置を「紙の上端からの長さ」で決めるように、
   番号の位置の計算（`pdf_engine.py` の `_label_geometry`）・帯と重なるかの判定（`src/app-review.js` の `stampHitsTimestampZone`）・
   プレビューの帯の表示（`src/app-preview.js`）を**3つ同時に**直す（どれかだけ直すと、プレビューと出力がずれる）。
3. 自動テスト（`test/stamp-output.test.js`）の、横向き・回転のケースに「帯より下にある」の判定を足す
   （今は帯の位置が分からないので、位置を参考に表示するだけで、合否は判定していない）。
4. 実際に出力した PDF で、朱色の番号の位置（上端・下端・左右の端からの mm）を測り、帯と重ならないことを確かめる。
5. AI への指示文（`assets/ai-prompt.md`）の「タイムスタンプ帯・実測値」と、[AI との約束](ai-contract.md) の位置の説明も直す。
