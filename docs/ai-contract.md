# AI の整理データの形（AI との約束）

LegalLeaves が読み込む「**AI の整理データ**」（JSON）の形を決めた文書です。
AI に渡す指示文（[`assets/ai-prompt.md`](../assets/ai-prompt.md)。アプリの「AI用プロンプトをコピー」で取り出せます）は、
この形で答えるよう AI に頼んでいます。どの AI を使う場合も、この形で返ってくれば LegalLeaves で読み込めます。

> この文書で「AI が〜する」と書いているところは、**指示文でそうするよう頼んでいる**という意味です。
> 実際にそのとおり答えるかは、使う AI の精度によります。そのため、大事なところはアプリの確認画面・出力前チェック・プレビューで人が確かめます。

役割の分け方は次のとおりです。

- **AI が決めること:** どのファイルが何の証拠か、証拠番号・枝番、標目・作成者・立証趣旨などの下書き、番号を押すページ・向き・位置
- **アプリが決めること:** 押す番号の文字（「甲第1号証」など）、ファイル名の整え方、同じ号証の結合、証拠説明書の表の書き方
- **人が決めること:** 最終的な確認。AI が迷ったところ（`needs_user_confirmation: true`）は、人が確かめるまで先へ進めません

書かれていない項目は「既定値」（下の表）で補います。知らない項目は無視します。

---

## 全体の形

```jsonc
{
  "schema_version": "2.0",          // この形の版（下の「形の版について」を参照）
  "evidence_explanation": { ... },  // 証拠説明書のファイルそのものについて
  "case": { ... },                  // 事件の情報（任意。証拠説明書の見出しに使う）
  "files": [ FileEntry, ... ],      // 必須。ファイル1つにつき1つ
  "warnings": [ "string", ... ]     // 任意。AI から利用者への注意（照合画面に表示）
}
```

### `evidence_explanation` — 証拠説明書のファイルについて

読み込んだファイルの中に**証拠説明書があるかどうか**と、その範囲です（番号の押印とは関係ありません）。

```jsonc
"evidence_explanation": {
  "exists": true,                                  // 証拠説明書があるか
  "file_name": "証拠説明書.pdf",                    // その元のファイル名。なければ null
  "first_evidence_number": "甲001",                // 説明書に載っている最初の番号
  "last_evidence_number": "甲003"                  // 同じく最後の番号
}
```

- 証拠説明書があるときは、**証拠説明書が番号の基準**です。AI には、各証拠の番号・標目を説明書に合わせ、勝手に振り直さないよう指示しています。
  食い違い（説明書にあるのにファイルが無い・その逆・番号や標目のずれ）があれば、そのファイルを `needs_user_confirmation: true` にするよう指示しています。
- アプリは、説明書の範囲と実際のファイルの番号を突き合わせ、足りない番号・範囲外の番号を照合画面に表示します。
- 証拠説明書のファイル自体は `type: "証拠説明書"` とし、番号は押さず、名前だけ整えます。

### `case` — 事件の情報（任意）

アプリが**証拠説明書の下書き**を作るとき、見出しに使います。

```jsonc
"case": {
  "case_name": "貸金返還請求事件",
  "case_number": "令和6年(ワ)第123号",
  "court": "東京地方裁判所",
  "plaintiff": "株式会社アルファ商事",
  "defendant": "ベータ工業株式会社",
  "party": "原告",                       // この書類を出す側（原告／被告、申立人／相手方）
  "lawyers": ["弁護士　山田　太郎"]       // 出す側の代理人
}
```

- 見出しに使うのは `court`・`case_number`・`party`・`lawyers` です。`case_name`・`plaintiff`・`defendant` は読み込みますが、今は使っていません
  （裁判所の公式ひな形の見出しに、事件名・当事者名の欄が無いため）。
- **取ってくる場所の限定:** `case` は、**この事件の主張書面（訴状・準備書面など）からだけ**埋めるよう指示しています。
  証拠（裁判例・書籍など）の中にある事件番号・当事者名・弁護士名は使わず、読み取れなければ null にするよう指示しています。
  空の欄は、証拠説明書では「●●」のまま残ります（Word で人の手で直します）。
- `party` が無いときは、証拠番号の記号（甲＝原告・乙＝被告）から補います。原告なのに乙の番号が付いているなどの食い違いは、照合画面で知らせます。

## FileEntry — ファイル1つ分

> **全角・半角:** `original_file_name` は元のファイル名を一字一句そのまま（幅も変えない）書きます。
> それ以外の内容（`title`・`suggested_base_name`・作成者の人名・`proof_purpose` など）は、英数字・スペース・かっこを**全角**で書きます
> （氏名は姓と名の間に全角スペース）。ファイル名にするときの半角への整えと、証拠説明書の表の整えは、アプリが行います。

```jsonc
{
  // ── ファイルの見分け・種類・番号 ──
  "original_file_name": "scan001.pdf",   // 実際のファイル名と突き合わせる。一字一句そのまま
  "type": "証拠",                         // 主張系｜証拠説明書｜証拠｜関連事件の申立｜その他
  "evidence_number": "甲001",            // 記号＋3桁のゼロ埋め。証拠でない・分からないときは null
  "branch_range": null,                  // 枝番。"2" や "1～3"。なければ null
  "title": "契約書",                      // 文書の表題（証拠なら証拠説明書の標目）
  "suggested_base_name": "甲001_契約書",  // 提出用ファイル名（拡張子なし）
  "needs_user_confirmation": false,      // true なら、人が確かめるまで先へ進めない
  "confirmation_question": null,         // 人に確かめてほしいこと（確認画面に表示）

  // ── 証拠説明書の下書きに使う（任意） ──
  "title_from_file": null,               // 説明書の標目とファイルの中身の標目が違うときの、中身側の標目
  "author": null,                        // 作成者（役割名なら「被告代理人」など）
  "author_alt": null,                    // 役割名にしたときの実名（確認画面で役割名／実名を選べる）
  "created_date": null,                  // 作成年月日。半角の和暦略記「R6.4.12」（令和R・平成H・昭和S）
  "proof_purpose": null,                 // 立証趣旨の下書き（人が確かめて直す）
  "original_or_copy": null,              // 「原本」／「写し」／null（下の説明）
  "digitized_from_paper": null,          // 紙をスキャン・撮影して電子化した証拠なら true
  "capture_kind": null,                  // 「写真」／「スクリーンショット」／「動画」／null
  "capture_subject": null,               // 撮影の対象
  "capture_datetime": null,              // 撮影日（半角の和暦略記 R6.4.12）
  "capture_location": null,              // 撮影の場所（写真・動画のみ）
  "capture_by": null,                    // 撮影者

  // ── 番号を押すページ・向き・位置（下の「stamps」） ──
  "stamps": [ ... ]
}
```

### 番号の書き方

- `evidence_number` は、並べ替えと照合の基準です。**3桁のゼロ埋め**（甲001）で書きます（甲001・甲002…甲010 が正しく並ぶように）。
  記号は2文字以上でもかまいません（企業間の訴訟の系列「甲A001」など。押す番号は「甲A第1号証」になります）。
- `suggested_base_name` も同じゼロ埋めの書き方にします。
- `branch_range` は、ファイル全体の枝番の範囲です（ファイル名・証拠説明書の表示用）。
- 紙面に押す「**甲第1号証**」の文字は、アプリが `evidence_number` と各 `stamps[].branch` から作ります。**AI は押す文字を書きません**。

### 証拠説明書の下書きの項目

証拠説明書が**無い**ときに、アプリが Word の下書きを作るための項目です。

- **表の書き方はアプリが整えます**（AI は素の値を入れればよい）。裁判所の公式ひな形に合わせ、号証欄は「甲001-1」の形
  （半角・3桁のゼロ埋め・枝番は半角ハイフン・枝番ごとに1行）、標目・作成者・立証趣旨の英数字は全角、作成年月日は半角の和暦です。
- **`original_or_copy`（原本・写し）:**
  - 「原本」… 相手が成立の真正を争い得る重要な書類（①契約書・合意書・覚書など署名押印のある書類 ②筆跡に意味がある手書きの書面 ③領収書・手形・小切手）。
  - null … 電磁的記録として提出するもの（メール・LINE の画面・Web の印刷・文献や裁判例や公的書類の写し・写真・音声・動画）。
    標目に原本・写しの記載が無いものは「民事訴訟法231条の2の電磁的記録として提出」の意味になります（テンプレートに定型の注記があります）。
  - 「写し」… **原則書きません**。紙の証拠で写ししか手元に無く、電磁的記録ではなく、あえて書証として出す例外のときだけです。
  - 迷ったら `needs_user_confirmation: true` にします。
  - 「原本」「写し」は、標目の欄の2行目に「（原本）」「（写し）」として入ります。
- **`digitized_from_paper`:** true で、かつ `original_or_copy` が null のとき、アプリが備考の欄に「紙を電子化」と書きます。
- **写真・スクリーンショット・動画（`capture_kind`）:** ほかの証拠と同じ6列の行で書きます。
  標目＝`title`（＋2行目に「撮影対象：…」、写真・動画は「撮影場所：…」）、作成年月日＝撮影日、作成者＝撮影者です
  （民事訴訟規則148条の、撮影の対象・日時・場所を明らかにする定めに対応）。`title` は種類が分かる短い言葉でかまいません。
- **`title_from_file`:** 証拠説明書の標目（`title` に入れる方が基準）と、ファイルの中身から読める標目が違うときだけ、中身側の標目を入れます。
  確認画面で「説明書の標目／ファイルの標目」を切り替えられます。

### `stamps` — 番号を押すページ・向き・位置（任意）

**1ページにつき1要素**の配列です。1つのファイルに枝番が複数あったり、1つの枝番が複数ページにまたがったりするため
（請求書と領収書の2枚組など）、AI がページごとに `branch`（枝番）を決めます。

```jsonc
"stamps": [
  {
    "page": 1,                 // 対象のページ（1始まり）
    "branch": "1",             // このページに押す枝番。枝番が無ければ null
    "draw_label": true,        // true＝番号を押す／false＝押さずに向きだけ直す（番号が既に入っている等）
    "rotate_degrees": 0,       // 読める向きに直す角度。0｜90｜180｜270（時計回り）
    "position": {              // 読める向きに直した紙面での位置（下の「位置の決め方」）
      "x": 0.93,
      "y": 0.07,
      "anchor": "top-right"
    },
    "font_size_pt": 18,        // 省略可
    "color": "#C80000"         // 省略可（朱色寄りの赤）
  }
]
```

**番号のある証拠で `stamps` が無いとき**は、1ページ目の右上（既定の位置）に番号を押します。
`stamps` はあるが全部が「押さない・向きもそのまま」のときは、押しません（番号が既に入っている証拠など）。

**どのページに押すか:**

- 原則、AI に内容とファイル名を見て決めてもらいます。**少しでも確信が持てなければ** `needs_user_confirmation: true` にし、`confirmation_question` で人に確かめるよう指示しています。
- 枝番ごとに**別の PDF に分かれている**ときは、それぞれの先頭ページだけに押します。
- 1つの枝番が複数ページにまたがるときは、その枝番の**先頭ページに1回**だけ。続きのページは `stamps` に入れません。
- **1つの PDF に複数の枝番がまとめてスキャンされている**ときは、各枝番の先頭ページに、その枝番を `branch` に入れた要素を作ります
  （`branch_range` は全体の範囲 "1～2"）。区切りの手がかりは ①証拠説明書の枝番ごとの行 ②主張書面の引用（「請求書（甲5の1）」など）
  ③紙面の変わり目、の順です。区切り・枝番ごとの標目・根拠を `confirmation_question` に書き、**必ず** `needs_user_confirmation: true` にします。
  アプリは確認画面の「ページで枝番に分ける」の入力欄に区切り（例 "1-3, 4-5"）を下書きします。**分けるのは人が確かめてから**です。

## 押す番号の文字（アプリが作る）

`stamps` の各要素ごとに、`evidence_number` とその要素の `branch` から、アプリが同じ規則で作ります。

1. `evidence_number` を記号と番号に分けます（`"甲001"` → 記号「甲」・番号 1）。
2. 「{記号}第{番号}号証」にします（**ゼロ埋めは外す**。例: 甲第1号証）。
3. `branch` があれば、末尾に「の{branch}」を付けます（例: 甲第1号証の1）。
4. 押すのは、`evidence_number` があり、かつ `draw_label` が false でないときだけです。

> 例: `evidence_number: "乙012"`・`branch: null` → **乙第12号証**
> 例: `evidence_number: "甲001"`・`branch: "2"` → **甲第1号証の2**

## 同じ号証の結合（アプリが行う）

枝番が**別のファイルに分かれている**ときは、出力するときに1つの PDF にまとめます。AI が結合を指示する必要はありません。

- **まとめる範囲:** `type` が証拠で、`evidence_number` が同じファイル。1ファイルだけならまとめません。
- **並び順:** 枝番の小さい順。AI にも、同じ号証のファイルは枝番順に並べて書くよう指示しています。
- **ページ番号:** `stamps[].page` は**それぞれのファイルの中での**ページ番号（1始まり）で書きます。まとめるときのずれはアプリが直します。
- **ファイル名:** まとめるときは、アプリが番号と標目から名前を作ります（例 `甲003_1～2_請求書.pdf`）。
  1ファイルだけの号証は、確認画面の「提出用ファイル名」（最初は `suggested_base_name`）の名前で保存します。
- **安全のために:** `evidence_number` が結合の唯一の手がかりなので、同じ号証の全部のファイルで**完全に同じ**書き方にするよう指示しています（表記や桁のゆれは不可）。
  枝番の重なり・抜け・順番が分からないときは `needs_user_confirmation: true` にするよう指示しています。
  アプリは、出力前チェックで枝番の重なり・抜けを知らせ、プレビュー（既定でオン）で結合後のページと番号の位置を人に見せてから書き出します。

## 位置の決め方（座標）

位置の解釈が食い違うと事故になるので、次を唯一の基準にします。

1. **基準の紙面:** `rotate_degrees` で**読める向きに直した後の紙面**（回転前の向きではありません）。
2. **原点と向き:** 紙面の**左上が (0, 0)**。x は右へ、y は**下へ**増えます。
3. **割合で書く:** x・y は、紙面の幅・高さに対する 0〜1 の割合です（用紙の大きさに関係なく使えます）。
4. **`anchor`:** (x, y) に合わせる、番号の枠の基準の角です。
   `top-right`（既定）なら、番号の枠の右上の角を (x, y) に置きます（そこから左下へ文字が伸びます）。
   使える値: `top-left`｜`top-right`｜`bottom-left`｜`bottom-right`｜`center`。

> 例: 右上に置く → `{ "x": 0.93, "y": 0.07, "anchor": "top-right" }`

**文字や見出しと重ならない位置へずらす:** 既定の位置（右上）に、見出し・ロゴ・透かし・本文・既にある押印などがあると判断したら、
空いている場所へ座標を書き換えるよう AI に指示しています（裁判例や文献の PDF は、上端に見出しや透かしがあることが多いため）。

- まずは**右寄せ（x 0.90〜0.93）のまま、重なるものの直下まで少しだけ下げる**（例 y 0.08〜0.11。見出しが厚いときだけ 0.13 程度まで）。
  下げすぎると「右上の番号」に見えなくなるためです。
- 右上がどうしても空かないときに限り、右下・左上など**ほかの角**へ。
- どの場合も、四辺は 3% 以上空け、x は 0.95 以下、y は1ページ目 0.07 以上（タイムスタンプ帯を避ける）・2ページ目以降 0.03 以上。

うまくずらせるかは AI の読み取りの精度によります。重なっていたら、プレビューで番号を**ドラッグして動かせます**。

**裁判所のタイムスタンプ帯を避ける:** mints に提出すると、各ファイルの**1ページ目**に、裁判所がタイムスタンプの帯を付けます。多くはページの上部です
（mints の A4 縦での実測で、上端から 8〜19mm ≒ y 0.027〜0.064。2ページ目以降には付きません）。
そのため、1ページ目の上側に置く番号は **y を 0.07 以上**にします。mints の A4 横・A3 での位置と、TreeeS で帯が付くかどうかは、まだ分かっていません
（[タイムスタンプ帯の測り方](timestamp-band-measurement.md)）。

## AI への指示の要点（指示文に反映している方針）

- **番号:** `evidence_number` は記号＋3桁のゼロ埋め（甲001）。押す文字は書かない（アプリが作る）。
- **ページごとの押印:** `stamps` に1ページ1要素。各要素に `branch`（無ければ null）。複数ページにまたがる枝番は先頭ページだけ。
- **向き:** 紙面が読める向きになる角度を `rotate_degrees` に（時計回り）。既に読める向きなら 0。
- **位置:** 既定は右上（`anchor: top-right`、x ≈ 0.93、y ≈ 0.07）。
- **重なりを避ける:** 本文・見出し・既にある押印・タイムスタンプ帯と重なりそうなら、位置をずらす。
  右寄せ（x 0.90〜0.93）を保ったまま、必要な分だけ下げるのが原則です。
- **余白:** 印刷で切れないよう、四辺は 3% 以上空ける（x ≤ 0.95。y は1ページ目 0.07 以上、2ページ目以降 0.03 以上）。
- **番号が既に入っている:** その要素の `draw_label: false`（押さずに向きだけ直す）。
- **迷ったら確認:** 押すページ・位置・枝番に少しでも確信が無ければ `needs_user_confirmation: true`。

## 書かれていないときの既定値（アプリが補う）

`stamps` の各要素に当てはめます。

| 項目 | 既定 |
|---|---|
| `stamps[].page` | 1 |
| `stamps[].branch` | null（枝番なし） |
| `stamps[].draw_label` | true（押す） |
| `stamps[].rotate_degrees` | 0 |
| `stamps[].position` を省略 | 右上（x = 0.93、y = 0.07、top-right） |
| `stamps[].position.anchor` | `top-right` |
| `stamps[].font_size_pt` | 18 |
| `stamps[].color` | `#C80000` |

## アプリが受け取るときに確かめること

- **壊れたデータを弾く:** JSON として読めないもの、ファイルの件数・文字の長さ・押印の指示の数が多すぎるもの、
  ページ番号が数でないものは、読み込まずにエラーを出します（AI の出力が途中で切れた・崩れた場合に備えるため）。
- **角度・位置の丸め:** `rotate_degrees` は 0・90・180・270 に丸め、`position` の x・y は 0〜1 に収めます。
- **ページの範囲:** 実際のページ数を超えるページの指定はエラーとして知らせます。
- **人の確認:** `needs_user_confirmation: true` のファイルは、確認画面で人がチェックを入れるまで先へ進めません。
- **書き出す前:** 出力前チェック（番号とファイル名の食い違い・枝番の重なりや抜け）を表示し、プレビュー（既定でオン）で人が確かめてから書き出します。

## 形の版について

- 今の形は `schema_version: "2.0"` です。
- アプリは今のところ、この値で動きを変えません（書かれていなくても読み込めます）。
  `stamps` が無い古い形の整理データも読み込め、その場合、番号のある証拠には既定の位置（1ページ目の右上）に番号を押します。
- 以前の形にあった `confidence`（AI の自信の度合い）・`notes`（AI のメモ）・`evidence_explanation.suggested_file_name`
  （証拠説明書のファイル名の案）は、アプリが使っていなかったため、AI が書く量を減らすために 5.2.6 で指示文から外しました。
  書かれていても無視します（古い指示文で作った整理データも、そのまま読み込めます）。
- 将来、形を大きく変えるときは、この値を上げ、古い値のデータの扱いをここに書きます。
