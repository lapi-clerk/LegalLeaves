# AI のアプリに LegalLeaves をつなぐ（MCP）

AI のアプリ（Claude のデスクトップアプリなど）に、LegalLeaves の「**点検する**」と「**確認画面で開く**」を道具として足すための窓口です。
つなぐと、AI が整理データを作ったあと、**人に渡す前に自分で点検して直し**、
**読み込みと貼り付けが済んだ状態で、確認画面を開く**ことができます。

整理データを作るだけなら、つなぐ必要はありません（指示文を貼ってファイルを渡せば作れます）。
つなぐ利点は、貼り付けてから誤りに気づいて AI に戻る往復と、ファイルを入れて貼り付ける手間が減ることです。

MCP（Model Context Protocol）は、AI のアプリに道具を足すための共通の決まりで、特定の AI のものではありません。
MCP に対応した AI のアプリなら、同じ設定でつなげます。

> **試験的な機能です。** つなぐには、AI のアプリの設定ファイルを書き換える必要があるため、パソコンの設定に慣れた方向けです。
> 操作説明書には、この機能があることだけを書き、手順はこの文書に寄せています。
>
> 5.5.0 から入っています（5.4.6 までには、ありません）。
> Claude のデスクトップアプリ（Windows）に、インストーラで入れた LegalLeaves をつないで確かめました。
> **Claude 以外の AI のアプリは、まだ試していません。**

## できること・できないこと

AI に出す道具は 3 つだけです。

| 道具 | 中身 |
| --- | --- |
| `legalleaves_format` | 整理データの形（AI への指示文）を読む。アプリの「AI用プロンプトをコピー」と同じ文で、事務所の書き方メモも含む |
| `legalleaves_check` | 整理データとフォルダのファイルを突き合わせて点検する。結果の形は [`check-entry.md`](check-entry.md) と同じ |
| `legalleaves_open` | 整理データとフォルダを、LegalLeaves の確認画面に開く（利用者のパソコンに窓が開く）。下の「確認画面で開く」 |

- **AI は提出用のファイルを書き出せません。** 書き出す道具を出していません。書き出しは、人が LegalLeaves の確認画面で確かめてから行います。
  確認画面で開く道具も、読み込みと貼り付けを代わりに行うだけで、何も書き出しません。
- **AI が点検したり開いたりできるのは、設定で決めたフォルダの中だけです**（下の「設定」）。それ以外のフォルダは、ファイル名も返しません。
- LegalLeaves 自身は、外部へ何も送りません。ファイルも書きません（開くときの整理データも、ファイルに書かずに窓へ渡します）。ネットワークの口も開きません。
- 点検の結果は、人が確かめる前の下書きの状態です。
- 点検が見るのは、形式・ファイルとの照合・番号と名前の食い違いです。標目・立証趣旨などの中身が正しいかは見ていません。
- 前に書き出した「提出用ファイル」という名前のフォルダは読みません（読まなかったことは結果に書きます。[`check-entry.md`](check-entry.md)）。

### 知っておくこと — AI に渡るもの

- LegalLeaves が AI に返すのは、**ファイル名と、整理データに書いてあること（番号・標目など）と、注意の文**です。
  PDF の本文など、**ファイルの中身は返しません**。
- 標目などは、AI がファイルを読んで、自分で書いたものです。AI がファイルを読めるのは、AI のアプリの側で、そのフォルダを使えるようにしたときです
  （LegalLeaves の設定とは別の許可です。下の「おすすめの使い方」）。
- LegalLeaves が返したものは、AI のアプリが AI の提供元へ送って、続きを考えます。つまり、**ファイル名などは AI の提供元に渡ります**。
  これは「AI にファイルを渡して整理データを作ってもらう」ときと同じ範囲で、新しく外へ出るものが増えるわけではありませんが、
  どこまで渡してよいかは、使う AI の契約（学習に使われないか・保存される期間）で決めてください。

## おすすめの使い方 — 作業用のフォルダを 1 つ決めておく

まず、提出の準備に使うフォルダを 1 つ、自分で作ります（名前と場所は自由です。ここでは、ドキュメントの中に作った「LegalLeaves作業用」とします）。
そのフォルダを、次の「設定」で、AI に扱わせてよいフォルダとして書いておきます。
あとは、提出に使う書類をそこへ入れて、AI に次のように頼みます。

```
作業用フォルダに今回の書類を保存したので、LegalLeaves で確認画面まで進めてください。
```

- 設定は最初の 1 回だけです。案件が変わっても、書き換えません
- AI が扱えるのは、いまそこに入っているファイルだけです。ほかの案件のフォルダは、範囲の外です
- **提出が済んだら、中を空にしてください。** 前の案件のファイルが残っていると、次の案件のファイルと混ざって読み込まれます
- AI にファイルの中身を読ませるには、AI のアプリの側でも、そのフォルダを使えるようにする必要があります。
  AI のアプリによっては、フォルダを使えるようにすると、ファイルの中身が提供元のサーバへ送られ、AI がファイルを書き換える・消す許可も
  含まれます（Claude のデスクトップアプリでは、許可を求める画面にそう書いてあります）。作業用のフォルダだけを許可すれば、AI に見せる範囲を小さく保てます

## 設定

AI のアプリの MCP の設定に、次の形で足します（Claude のデスクトップアプリなら、設定 → 開発者 → 設定を編集 で開く
`claude_desktop_config.json`）。`--root` のあとに、上で作った作業用のフォルダを書きます。

```json
{
  "mcpServers": {
    "legalleaves": {
      "command": "C:\\Users\\<ユーザー名>\\AppData\\Local\\Programs\\LegalLeaves\\LegalLeaves.exe",
      "args": ["--mcp", "--root", "C:\\Users\\<ユーザー名>\\Documents\\LegalLeaves作業用"]
    }
  }
}
```

- `<ユーザー名>` は、パソコンのユーザー名に置き換えてください（エクスプローラーで `C:\Users` を開くと見えます）。
  作業用のフォルダを別の場所に作ったときは、その場所を書きます。区切りの `\` は、2 つ重ねて `\\` と書きます。
- `command` は LegalLeaves.exe の場所です（インストーラで入れたときは、上の場所です）。
- **設定ファイルは、AI のアプリを完全に終了してから書き換えてください。** Claude のデスクトップアプリは、動いている間に書き換えると、
  書いた内容が消えることがあります。
- `--root` は、「AI に扱わせてよいフォルダは、ここです」と LegalLeaves に教える印です。AI がこの外のフォルダを頼んでも、LegalLeaves が断ります。
  `"--root", "フォルダ"` の組を続けて書けば、いくつでも足せます。
- **`--root` を 1 つも書かないと、どのフォルダも扱えません**（形を読む道具だけが使えます）。何も書かなければ、何も通さない作りです。

### ほかの決め方と、案件どうしの仕切り

| `--root` に書くもの | 扱える範囲 | 案件どうしの仕切り |
| --- | --- | --- |
| 作業用のフォルダ（おすすめ） | いまそこに入っているファイル | 強い（中を空にしてから次を入れる） |
| 案件ごとのフォルダ | その案件のフォルダの中 | 強い。ただし、案件が変わるたびに設定を書き換える |
| 案件をまとめたフォルダ（全部の案件が入った、親のフォルダ） | その中の全部の案件 | 弱い。どの会話からも、全部の案件が対象になる |

仕切りを守るのは、LegalLeaves が範囲の外を断ることです。AI への指示（案件のフォルダに置く指示書など）で範囲を絞ることもできますが、
AI が従うことに頼る形なので、確実ではありません。

### 開発中の設定

```json
{
  "mcpServers": {
    "legalleaves-dev": {
      "command": "C:\\…\\LegalLeaves\\py\\.venv\\Scripts\\python.exe",
      "args": ["-m", "legalleaves", "--mcp", "--root", "C:\\…\\作業用のフォルダ"],
      "cwd": "C:\\…\\LegalLeaves\\py"
    }
  }
}
```

`cwd` を受け付けない AI のアプリでは、`PYTHONPATH` に `py` フォルダを入れてください。

## 確認画面で開く（`legalleaves_open`）

人が「ファイルを入れる → 整理データを貼り付ける → 照合して進む」をしたのと同じ状態で、LegalLeaves の窓を開きます。

- **人が貼り付けたときと、同じ確かめ方をします。** 画面は、渡された整理データを、貼り付けたときと同じように確かめ、
  「照合して進む」が押せる状態のときだけ先へ進みます。AI から渡されたものだけ確かめずに通す、という道はありません
- **形式の誤りがある整理データは開きません**（AI に誤りを返します）。フォルダに読み込めるファイルが無いときも開きません
- 開いた画面には、「AI のアプリなど、外から開きました」という知らせが、どの画面でも出ます
- 前に書き出した「提出用ファイル」のフォルダは読み込みません（点検と同じ。読み込まなかった件数を知らせに出します）
- 開くたびに、新しい窓が 1 つ開きます（すでに開いている LegalLeaves の作業には触りません）
- 窓口（MCP）を使わずに、同じことを起動の引数でもできます。

```
LegalLeaves.exe --open <整理データ.json> --files <フォルダ>
LegalLeaves.exe --open - --files <フォルダ>        （整理データを標準入力から渡す）
```

  誤りがあって開けないとき（フォルダが無い・整理データを読めない など）は、窓を出さずに、終了コード 1 で終わります。

## 使う流れ

1. AI に、作業用のフォルダのファイルを見せて「LegalLeaves で確認画面まで進めて」と頼む
2. AI が `legalleaves_format` で形を読み、整理データを作る
3. AI が `legalleaves_check` で点検し、指摘（フォルダに無いファイル・番号の食い違い・形式の誤り）を直す
4. AI が `legalleaves_open` で、確認画面を開く
5. 人が確認画面で確かめて、書き出す

「開いて」と頼まなければ、AI は整理データを会話に出します。人がそれを貼り付けて進めることもできます。

## 確かめたこと・確かめていないこと

確かめたこと（2026-11。Windows の Claude のデスクトップアプリに、インストーラで入れた 5.5.0 をつないだ）:

- 通常の会話から頼むと、AI は、形を読む → 整理データを作る → 点検する → 確認画面で開く、の順で動いた。書き出そうとはしなかった
- 点検でファイル名の取り違えが見つかると、AI は直して点検し直した。番号の飛び（枝番の欠け）は勝手に直さず、人に確かめる点として伝えた
- 設定で決めた外のフォルダを頼むと、LegalLeaves が断り、AI はそのことを利用者に伝えた（ファイルを写すなどの回り道はしなかった）

確かめていないこと:

- **Claude 以外の AI のアプリ。** MCP に対応していても、パソコンの中のプログラムを起動してつなぐ形に対応しているかは、
  アプリによって違う。

試して、採らなかったこと:

- **AI のアプリが伝えてくる「この会話で使ってよいフォルダ」に合わせる形。** 伝わるときと伝わらないときがあり、伝わっても、
  そのとき開いている全部の会話のフォルダがまとめて届くため、案件ごとに分けられなかった。フォルダの決め方も増えて説明が難しくなるので、
  設定に書く 1 通りにした
- **AI のアプリの設定を、LegalLeaves が代わりに書く機能**（画面の「つなぐ」ボタンなど）は作らない。AI のアプリごとに設定の場所や形が違い、
  変わるたびに追いかけ続けることになるため。用意するのは、共通の決まり（MCP）に沿った窓口までにする

## 作り

- 窓口の本体は `py/legalleaves/mcp_server.py`。外部の部品は使わず、標準ライブラリだけで、MCP のうち道具の呼び出しに必要な部分
  （`initialize`・`ping`・`tools/list`・`tools/call`）を話します。
- 判定は `py/legalleaves/core/`（画面と同じ表でそろえたもの）。点検の組み立ては `py/legalleaves/check.py`。
- テストは `py/tests/mcp_entry.py`（窓は出さない）と `py/tests/e2e_open.js`（確認画面で開く）。
  配布用の exe に当てるときは、`LL_EXE` に exe の場所を入れて動かします
  （例: `$env:LL_EXE="<…>\LegalLeaves.exe"; py\.venv\Scripts\python py\tests\mcp_entry.py`）。
