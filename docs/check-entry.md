# 点検する（`--check`）— AI のエージェント向けの入口

AI の整理データ（[`ai-contract.md`](ai-contract.md) の形）を、**人に渡す前に確かめる**ための入口です。
人が画面に貼り付けて「次へ」を押したときと同じ判定（形式チェック → 照合 → 出力前チェック → 出力の計画）を通し、
その結果を JSON に書きます。窓は出ません。

> 5.5.0 から入っています（5.4.6 までには、ありません）。開発中は下の「開発中の呼び方」で動かせます。
> 配布用と同じ作り方で作った exe で動くことは、確かめてあります（2026-11-11）。

```powershell
LegalLeaves.exe --check <整理データ.json> --files <フォルダ> --report <結果.json>
```

| 引数 | 中身 |
| --- | --- |
| `--check` | AI の整理データ（JSON・UTF-8）。人が貼るものと同じ形で、エージェント専用の項目はありません |
| `--files` | 提出するファイルを入れたフォルダ。画面にフォルダを落としたときと同じ決まりで読みます（中のフォルダもたどります）。ただし、前に書き出した「**提出用ファイル**」という名前のフォルダは読みません（下の「読まないフォルダ」） |
| `--report` | 結果を書くファイル（`.json`）。**`--files` のフォルダの中に限ります**。名前だけを渡すと、そのフォルダに書きます |
| `--include-outputs` | （任意）「提出用ファイル」のフォルダも読みます。書き出し済みのファイルを整え直すときなどに付けます |

### 読まないフォルダ

案件のフォルダの中に、前に書き出した「提出用ファイル」のフォルダが残っていると、元のファイルと書き出し済みのファイルの
両方を読むことになり、同じ証拠が 2 つあるように見えます。そこで、点検ではこの名前のフォルダを読みません。
読まなかったフォルダと、その中のファイルの数は、結果の `skippedFolders` に書きます（黙って減らしません）。

- 判別は**フォルダの名前だけ**です。名前を変えた・別の場所へ移した書き出し済みのファイルは、読みます
- 画面にフォルダを落としたときは、これまでどおり全部読みます（書き出し済みのファイルを読み直す使い方があるため）

AI のアプリから道具として呼ぶ形（MCP）は [`mcp.md`](mcp.md) を見てください。判定と結果の形は同じです。

## 決まり

- **提出用のファイルは書き出しません。** 書くのは結果の JSON 1 つだけです。書き出しは、人が確認画面で確かめてから行います。
  エージェントに書き出しまでさせる入口は、作りません（書き出す前に、必ず人が確認画面で確かめるためです）。
- 結果は**人が確かめる前の下書きの状態**です。確認画面で人が直せば、番号も名前も変わります。
- **点検が見るのは、形式・ファイルとの照合・番号と名前の食い違いです。** 標目・作成者・立証趣旨などの中身が正しいかは見ていません。
  「点検が通った」は「中身も正しい」ではありません（結果の `note` にもそう書いています）。
- 結果にはファイル名が入るので、フォルダの外には書きません。ファイルの場所（フルパス）は結果に入れません。
- 外部へは何も送りません。整理データをアプリの保存場所に残しません。

## 終了コード

| コード | 意味 |
| --- | --- |
| 0 | 点検した。問題の有無は結果の JSON を見る（形式の誤りも、結果の `formatError` に書く） |
| 1 | 点検できなかった（引数・フォルダ・結果を書く先の誤り）。結果は書かない |

配布用の exe は黒い画面を持たないので、手で実行しても文字は出ません。ほかのプログラムから起動したときは、
点検できなかった理由が標準エラー出力に UTF-8 で出ます。呼ぶ側は終了を待ち、終了コードと結果の JSON を見てください
（PowerShell なら `Start-Process -Wait -PassThru`）。

## 結果の形

```jsonc
{
  "tool": "LegalLeaves", "version": "5.x.x", "kind": "check", "reportVersion": 1,
  "note": "人が確認する前の下書きの状態です。…",
  "ok": true,                 // 形式チェックを通ったか。false のときは formatError だけを見る
  "formatError": "",          // 形式の誤り（貼り付けたときに画面に出るものと同じ文）
  "rejectedFiles": [          // フォルダにあるが、受け付けなかったファイル
    { "name": "図.gif", "reason": "画像は .jpeg / .png のみ対応です。…" }
  ],
  "skippedFolders": [         // 読まなかったフォルダ（前に書き出した「提出用ファイル」）と、中のファイルの数
    { "folder": "提出用ファイル", "files": 3 }
  ],
  "summary": {
    "files": 4,               // 受け付けたファイル
    "matched": 3,             // 整理データに対応する項目があった
    "unmatched": 1,           // 対応する項目が無かった
    "missingFiles": 1,        // 整理データにあるのに、フォルダに無い
    "needsConfirmation": 2,   // 確認画面で人が確かめるまで先へ進めない（誤りの数ではない。AI が付けた要確認も数える）
    "outputIssues": 0,        // 出力前チェックの知らせ
    "outputs": 3              // このまま進めたときにできるファイル
  },
  "files": [
    {
      "name": "甲2の2_領収書.pdf",
      "matched": true,
      "kind": "証拠",
      "evidenceNumber": "甲002", "branchRange": "2",
      "title": "領収書",
      "submitName": "甲002_2_領収書.pdf",   // 結合する号証は、outputs の名前になる
      "needsConfirmation": true, "confirmText": "日付が読めません。",
      "numberMismatch": null   // 提出用ファイル名の番号と証拠番号の食い違い（number / badNumber / missing / bothBad / nameEmpty）
    }
  ],
  "missingFiles": ["甲3_写真.pdf"],
  "consistency": null,         // 証拠説明書に書かれた番号の範囲との突き合わせ（証拠説明書が無ければ null）
  "warnings": ["…"],           // AI の注意と、アプリが見つけた注意（提出者側と記号の食い違いなど）
  "outputIssues": [{ "file": "…", "text": "…" }],
  "outputs": [
    { "name": "甲002_1～2_請求書.pdf", "evidenceNumber": "甲002", "from": ["甲2の1_請求書.pdf", "甲2の2_領収書.pdf"] }
  ],
  "explanationExists": false,  // フォルダの中に証拠説明書があるか（整理データの記載）
  "explanationFileName": "証拠説明書(甲001～甲002).docx"
}
```

`reportVersion` は、項目の意味を変えたときに上げます。項目を足すだけなら上げません（知らない項目は無視してください）。

## エージェントの使い方の目安

1. 整理データを作る
2. 点検する
3. `ok` が false なら形式を直す。`missingFiles`・`unmatched`・`outputIssues`・`warnings` を見て、整理データを直せるところは直す
4. 直せないところ・迷うところは、`needs_user_confirmation` を付けて人に渡す（点検の結果を人に見せるのもよい）
5. 人が LegalLeaves の確認画面で確かめ、書き出す

## 開発中の呼び方

```powershell
cd py
.venv\Scripts\python -m legalleaves --check <整理データ.json> --files <フォルダ> --report <結果.json>
```

判定の本体は `py/legalleaves/core/`、入口は `py/legalleaves/check.py`、テストは `py/tests/check_entry.py`（`npm test` に入っています）。
