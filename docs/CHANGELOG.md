# 変更履歴（LegalLeaves）

各版で変わったことを、新しい順に書いています。
版の番号は、アプリの画面の上（ロゴの横）と、インストーラのファイル名に出ます。

**新しい版にするとき:** 今の版を消す（アンインストールする）必要はありません。新しい版のインストーラを実行するだけで、
新しい版に置き換わります。事務所の書き方メモ・最近使ったフォルダ・設定は、そのまま残ります。

## 5.2.6 — 公開に向けて、説明と表示を見直し

- 最初に公開する版です。インストーラは GitHub の Releases から入手できます。
- AI への指示文から、アプリが使っていなかった3つの項目（確からしさ・メモ・証拠説明書のファイル名の案）を外しました。
  AI が書く量が減ります。
- AI への指示文の書式を整えました（見出し・空行・箇条書き）。指示の文言は変えていません。
- TreeeS（裁判所の新しい電子提出の仕組み）を、説明書と画面の説明に足しました。
  拡張子は mints と同じです。タイムスタンプ帯の位置と一度のアップロードの上限は、mints で確かめた値のままです
  （TreeeS ではまだ確かめていません）。
- 画面の「このパソコン」を「LegalLeaves を入れたパソコン」に言い換えました。
- ヘルプのいちばん下にある、使っている部品とライセンス表示の場所を、今の版に合わせました。
- 操作説明書・README・AI との約束・タイムスタンプ帯の測り方を、初めて読む人に分かるように書き直しました。

## 5.2.5 — 一覧にも食い違いの印、入力中に欄が動かないように

- 番号とファイル名が食い違うファイルは、左の一覧にも「**要修正**」（オレンジ）・「**エラー**」（赤）の印を付けるようにしました
  （一覧では「甲000」がふつうの番号のように見えていたため）。
- 証拠番号を「甲0」のような正しくない値にしてから戻すと、「甲000」の空き枠（後で追加予定）が残っていたのを直しました。
  正しくない値にしたときは、元の番号も空き枠にしません。
- 欄を選んだときに知らせを消していたため、下の欄が上にずれて、入力している欄が動いたように見えていました。
  入力中は知らせを消さずに薄くして残し、Enter か欄を離れたときに中身を更新するようにしました。

## 5.2.4 — 証拠番号・ファイル名の欄を空にしたときも知らせる

- 証拠番号と提出用ファイル名の両方を消したとき、何も知らせが出なかったのを直しました。
  赤のエラーで「証拠番号と提出用ファイル名が空です。証拠番号を入力してください」と出します。
- 証拠番号だけが空で、ファイル名に正しい番号があるときは「証拠番号を○にする」を出します
  （出力前チェックの「証拠番号がありません」の行にも出ます）。
- 提出用ファイル名だけが空のときは赤のエラーにし、「ファイル名を○で始める」（証拠以外は「ファイル名を標目から作る」）で作り直せます。
- 番号とファイル名の両方が正しくないときは、「**最初の値に戻す**」で、そのファイルの証拠番号・枝番・提出用ファイル名だけを
  確認画面を開いたときの値（AIの値、またはファイル名から読んだ値）に戻せるようにしました。

## 5.2.3 — 番号の食い違いの知らせを、入力し終えてから出す

- 食い違いの知らせを、証拠番号・枝番・提出用ファイル名の欄を**入力している間は出さず**、Enter を押すか
  欄を離れたときに出すようにしました（入力の途中で「甲000で始める」のような誤った案内が出ていたため）。
  枝番とファイル名の欄でも Enter で確定できます。
- 片方が番号として正しくないときは、**正しいほうに合わせるボタンだけ**を出すようにしました
  （証拠番号が「甲0」ならファイル名の番号に合わせる、ファイル名に番号が無ければ証拠番号に合わせる）。
  **両方とも正しくないときは赤のエラー**で知らせます（出力前チェックにも出ます）。
- 証拠番号を「甲0」のような正しくない値にしたとき、提出用ファイル名まで「甲000_…」に書き換わっていたのを直しました
  （ファイル名は、正しい番号にしたときだけ追従します）。

## 5.2.2 — ファイル名の番号と証拠番号を、ボタンで合わせる

- 提出用ファイル名の番号と証拠番号が食い違うと、確認画面の欄の下に知らせを出し、
  「**証拠番号を○にする**」「**ファイル名を○で始める**」のボタンで片方に合わせられるようにしました。
  出力前チェックの行にも同じボタンを付け、確認画面に戻らずに直せます。
  ファイル名を書き換えたときに証拠番号を自動では変えません（入力の途中で番号が動き、空き枠や結合が
  勝手に起きるため。どちらに合わせるかは人が決めます）。
- 出力前チェックで、同じ番号の書き方の違い（証拠番号 甲004 に対して「甲4_写真.pdf」など）は食い違いにしないようにしました。

## 5.2.1 — 向きのボタン・大きな PDF・番号の抜けの表示

### 向きはボタンで直します
- 向きのプルダウンをやめ、「**↺ 左に90°**」「**↻ 右に90°**」「**180°**」「元に戻す」のボタンにしました。
  確認画面では「元ファイルを見る」の**プレビューのすぐ上**にあり、押すとプレビューもその向きに変わります
  （これまでは確認画面のプレビューは回りませんでした）。出力前のプレビューにも同じボタンがあります。
- **写真を「90°」回すと、PDF と逆の向き（反時計回り）に回っていた**のを直しました。PDF・写真とも、
  右に90° は時計回りです（AI の整理データの回転の向きとも合わせました）。

### 大きな PDF を出力できなかったのを直しました
- 1つの中に 75MB を超えるデータがある PDF（高画質でスキャンした図面など）が、プレビューも書き出しもできませんでした。
  1ファイル 200MB（mints の上限）を超えるものまで扱えるようにしました。
- 保存の前の後片付け（削除したメタデータを残さない処理）を作り直し、大きな PDF の書き出しが速くなりました
  （試験用の 142MB と 116MB の PDF で、プレビュー 58秒 → 4秒、書き出し 54秒 → 3秒）。
  削除にした作成者名・XMP が出力に残らないことは、試験でも確かめています。
- 部品が英語で返すエラーは、「このファイルを処理できませんでした（詳細: …）」と日本語で示すようにしました。

### そのほか
- 出力前チェックを、出力画面の**いちばん上**に移しました（画面の下にあり、気づきにくかったため）。
- 読み込んだファイルの番号に抜けがあるとき（甲1 と 甲4 だけ等）、一覧のその位置に
  「甲2・甲3 は今回のファイルにありません」と薄く示します。「後で追加予定にする」で空き枠にできます
  （後から追加する分だけを読み込んだときは、前に出した番号が抜けて見えるので、自動では空き枠にしません）。
- 出力前のプレビューで、**証拠説明書（下書き）の中身を表で確かめられる**ようにしました
  （証拠説明書を作る設定で、立証趣旨が1つでも入っているとき）。Word への変換はしないので軽いです。
- 完了画面の合計の大きさを、一覧の上に枠で目立つように出しました。

## 5.2.0 — 出力前チェック・証拠説明書の欄・容量の表示・写真の向き

### 出力前チェック
- 出力の画面の上に「**出力前チェック**」を足しました。提出用ファイル名の番号と押す番号の食い違い、
  枝番の重なり・飛び・混在、番号の無い証拠、同じ名前のファイルができることを一覧で知らせます。
  押すと確認画面のその証拠へ戻ります（そのまま作成することもできます）。食い違いが無ければ1行だけ出ます。
- **提出用ファイル名の欄は、書いてあるとおりの名前で保存する**ようにしました。これまでは、1ファイルの号証でも
  保存する名前を番号と標目から作り直していたため、欄を手で直しても保存される名前に反映されませんでした
  （枝番を1つのPDFにまとめるときは、これまでどおり番号と標目から作ります）。

### 確認画面で証拠説明書の欄を書き込めます
- 証拠ごとに「証拠説明書の欄」を開いて、作成者・作成日（写真などは撮影者・撮影日）・原本／写し・立証趣旨を
  書き込めるようにしました。書いた内容は証拠説明書の下書きに入ります。

### 容量の表示
- 完了画面とプレビューの一覧に、ファイルごとの大きさを出すようにしました。
- 完了画面に合計の大きさを出し、mints の一度のアップロードの上限（200MB）を超えるときは、
  何回かに分ける目安を示します。1つで上限を超えるファイルは赤で示します。

### 写真の向き
- スマートフォンの写真に付いている**向きの情報**を読み、エクスプローラーやブラウザで見えるのと同じ向きで
  PDFにするようにしました。これまでは向きの情報を見ていなかったため、縦に持って撮った写真が横向きのPDFになることがありました。
  向きを推測して変えることはしません。確認画面やプレビューで回した分は、見えている向きに上乗せされます。

### そのほか
- 5.1.0 の変更履歴にある「提出用ファイル名の番号が古いままになる不具合」について: 実際に保存される名前は
  新しい番号で作られていました。古い番号のまま残っていたのは**欄の表示**です（上の「提出用ファイル名の欄」の変更で、表示と保存がそろいました）。

## 5.1.0 — 後から証拠を追加しやすく、確認画面を使いやすく

### 後から証拠を追加しやすくなりました
- 読み込み画面に「**AIを使わずに進む**」を足しました。ファイル名を「甲1の2_領収書.pdf」のように
  号証番号から始めておくと、AIの整理データなしで番号を決めて確認画面へ進めます（少しの追加向け）。
  操作説明書に「後から証拠を追加するとき」の章を足し、追加分だけ AI に渡す方法も書きました。

### 確認画面の改善
- 「枝番に分ける」を「**甲1の1にする**」（選んでいる証拠の番号が入ります）に改名しました。
  「ページで枝番に分ける」との違いを分かりやすくするためです。
- 画面が広いときは、選んだファイルのプレビューを最初から開き、一覧も最初から全件を表示します。
  要確認だけを表示しているときは「ほか○件は表示していません」と示し、ボタン名も「全件を表示」にしました。
  作業の途中で窓を広げたときもプレビューが開き、狭めたときは閉じます（ボタンで開け閉めしたあとは、そのときの状態のまま）。
- **証拠番号を書き換えても、提出用ファイル名の番号が古いままになる不具合を直しました**
  （例: 甲003を甲004に書き換えると「甲003_…pdf」に「甲第4号証」が押されていました）。
  あわせて、書き換えで途中の番号が空いたときは「後で追加予定」の空き枠として表示します。
- プレビューで、文字の少ないページを「表示できませんでした」と誤って注記することがあったのを直しました。

### インストーラ
- 最後の画面で、**デスクトップにショートカットを作るかを選べる**ようにしました（最初はチェックが入っています）。
  選んだ内容は覚えておき、次の更新でも同じ状態で始まります。
- アンインストールのとき、タスクバーにピン留めしたショートカットも消すようにしました。

### そのほか
- 操作説明書の PDF の作り方を変えました（中身は同じです）。同梱しているソフトのライセンス表示を、実際に同梱している部品に合わせて直しました。

## 5.0.0 — 軽く・速くなりました（インストーラ版）

### 起動が速く、容量が小さくなりました
- 中身の作り（Electron）を、Windows に入っている部品を使う軽い作り（Python＋WebView2）に変えました。
  **画面と操作はこれまでと同じ**です。
  | | 4.1.0 まで | 5.0.0 |
  |---|---|---|
  | 起動して画面が出るまで | 約12秒 | **約2秒** |
  | 配布ファイル | 約100MB | **約21MB** |
  | パソコンに入る大きさ | 約390MB（起動のたびに一時フォルダへ展開） | **約43MB** |
- 出力されるPDF・証拠説明書は、これまでと同じものになることを確かめています
  （同じ材料で新旧を出力し、ページを画像にして見比べました）。

### インストーラで入れる形になりました
- `LegalLeaves-Setup-5.0.0.exe` を実行して入れます。**管理者の権限は必要ありません**（各自のユーザーに入ります）。
  デスクトップとスタートメニューにアイコンができ、スタートメニューには操作説明書も入ります。
- **アンインストールは Windows の「設定 → アプリ」から**できます。その際「事務所の書き方メモ・履歴・設定も
  削除しますか？」と確認し、「はい」なら LegalLeaves を入れたパソコンに何も残りません。作業用の一時ファイルも一緒に消えます。

### そのほか
- 終了時に、画面の部品が使った作業データを残さないようにしました（以前は一部が残り続けていました）。
- パスワードで閲覧が保護されていないPDF（編集だけ制限されたもの）は、そのまま扱えるようにしました。
  閲覧にパスワードが必要なPDFは、理由を表示して止まります。

- **4.1.0:** 1つの PDF にまとめてスキャンした枝番を、ページで分けられるように
