# 変更履歴（LegalLeaves／旧・楽々mints）

> v4.0.0 でアプリ名を **楽々mints → LegalLeaves** に改称しました。
> v3.x以前の記載にある「楽々mints」は当時の名称です（履歴として残しています）。

バージョンはアプリのヘッダとexeのプロパティ（製品バージョン）に表示されます。
v5 からは `py/legalleaves/__init__.py` の `__version__` が正です（`package.json` の `version` もそろえます）。

## 5.2.5 — 一覧にも食い違いの印、入力中に欄が動かないように

5.2.4 を試していただいた結果をもとにした直しです。
- 番号とファイル名が食い違うファイルは、左の一覧にも「**要修正**」（オレンジ）・「**エラー**」（赤）の印を付けるようにしました
  （一覧では「甲000」がふつうの番号のように見えていたため）。
- 証拠番号を「甲0」のような正しくない値にしてから戻すと、「甲000」の空き枠（後で追加予定）が残っていたのを直しました。
  正しくない値にしたときは、元の番号も空き枠にしません。
- 欄を選んだときに知らせを消していたため、下の欄が上にずれて、入力している欄が動いたように見えていました。
  入力中は知らせを消さずに薄くして残し、Enter か欄を離れたときに中身を更新するようにしました。

## 5.2.4 — 証拠番号・ファイル名の欄を空にしたときも知らせる

- 証拠番号と提出用ファイル名の両方を消したとき、何も知らせが出なかったのを直しました。
  赤のエラーで「証拠番号と提出用ファイル名が空です。証拠番号を入力してください」と出します。
- 証拠番号だけが空で、ファイル名に正しい番号があるときは「証拠番号を○にする」を出します
  （出力前チェックの「証拠番号がありません」の行にも出ます）。
- 提出用ファイル名だけが空のときは赤のエラーにし、「ファイル名を○で始める」（証拠以外は「ファイル名を標目から作る」）で作り直せます。
- 番号とファイル名の両方が正しくないときは、「**最初の値に戻す**」で、そのファイルの証拠番号・枝番・提出用ファイル名だけを
  確認画面を開いたときの値（AIの値、またはファイル名から読んだ値）に戻せるようにしました。

## 5.2.3 — 番号の食い違いの知らせを、入力し終えてから出す

5.2.2 を試していただいた結果をもとにした直しです。
- 食い違いの知らせを、証拠番号・枝番・提出用ファイル名の欄を**入力している間は出さず**、Enter を押すか
  欄を離れたときに出すようにしました（入力の途中で「甲000で始める」のような誤った案内が出ていたため）。
  枝番とファイル名の欄でも Enter で確定できます。
- 片方が番号として正しくないときは、**正しいほうに合わせるボタンだけ**を出すようにしました
  （証拠番号が「甲0」ならファイル名の番号に合わせる、ファイル名に番号が無ければ証拠番号に合わせる）。
  **両方とも正しくないときは赤のエラー**で知らせます（出力前チェックにも出ます）。
- 証拠番号を「甲0」のような正しくない値にしたとき、提出用ファイル名まで「甲000_…」に書き換わっていたのを直しました
  （ファイル名は、正しい番号にしたときだけ追従します）。

## 5.2.2 — ファイル名の番号と証拠番号を、ボタンで合わせる

- 提出用ファイル名の番号と証拠番号が食い違うと、確認画面の欄の下に知らせを出し、
  「**証拠番号を○にする**」「**ファイル名を○で始める**」のボタンで片方に合わせられるようにしました。
  出力前チェックの行にも同じボタンを付け、確認画面に戻らずに直せます。
  ファイル名を書き換えたときに証拠番号を自動では変えません（入力の途中で番号が動き、空き枠や結合が
  勝手に起きるため。どちらに合わせるかは人が決めます）。
- 出力前チェックで、同じ番号の書き方の違い（証拠番号 甲004 に対して「甲4_写真.pdf」など）は食い違いにしないようにしました。

## 5.2.1 — 5.2.0 の試用で見つかった点の直し（向きのボタン・大きな PDF・番号の抜け）

5.2.0 を試していただいた結果をもとにした直しです。**5.2.0 の上からそのまま入れれば更新できます**。

### 向きはボタンで直します
- 向きのプルダウンをやめ、「**↺ 左に90°**」「**↻ 右に90°**」「**180°**」「元に戻す」のボタンにしました。
  確認画面では「元ファイルを見る」の**プレビューのすぐ上**にあり、押すとプレビューもその向きに変わります
  （これまでは確認画面のプレビューは回りませんでした）。出力前のプレビューにも同じボタンがあります。
- **写真を「90°」回すと、PDF と逆の向き（反時計回り）に回っていた**のを直しました。PDF・写真とも、
  右に90° は時計回りです（AI の整理データの回転の向きとも合わせました）。

### 大きな PDF を出力できなかったのを直しました
- 1つの中に 75MB を超えるデータがある PDF（高画質でスキャンした図面など）が、プレビューも書き出しもできませんでした。
  1ファイル 200MB（mints の上限）を超えるものまで扱えるようにしました。
- 保存の前の後片付け（削除したメタデータを残さない処理）を作り直し、大きな PDF の書き出しが速くなりました
  （試験用の 142MB と 116MB の PDF で、プレビュー 58秒 → 4秒、書き出し 54秒 → 3秒）。
  削除にした作成者名・XMP が出力に残らないことは、試験でも確かめています。
- 部品が英語で返すエラーは、「このファイルを処理できませんでした（詳細: …）」と日本語で示すようにしました。

### そのほか
- 出力前チェックを、出力画面の**いちばん上**に移しました（画面の下にあり、気づきにくかったため）。
- 読み込んだファイルの番号に抜けがあるとき（甲1 と 甲4 だけ等）、一覧のその位置に
  「甲2・甲3 は今回のファイルにありません」と薄く示します。「後で追加予定にする」で空き枠にできます
  （後から追加する分だけを読み込んだときは、前に出した番号が抜けて見えるので、自動では空き枠にしません）。
- 出力前のプレビューで、**証拠説明書（下書き）の中身を表で確かめられる**ようにしました
  （証拠説明書を作る設定で、立証趣旨が1つでも入っているとき）。Word への変換はしないので軽いです。
- 完了画面の合計の大きさを、一覧の上に枠で目立つように出しました。

## 4.1.0 — 1つのPDFにまとめてスキャンした枝番を、ページで分けられるように

### 新しい機能
- **1つのPDFを、ページの範囲で枝番に分けられる**ようになりました。
  請求書と領収書をまとめて1つのPDFにスキャンしたときなど、確認画面で「**ページで枝番に分ける**」を押し、
  `1-3, 4-5` のように入力すると、1〜3ページ目が 甲◯の1、4〜5ページ目が 甲◯の2 になります。
  - 分けた枝番は、一覧では別々のファイルと同じように扱えます（並べ替え・標目の修正など）。
  - 出力時は元のPDFから該当ページを切り出し、**1つのPDF**（例 `甲003_1～2_請求書.pdf`）にまとめます。
    番号は**各枝番の先頭ページにだけ**押されます。
  - ページの抜け・重なり・全ページ数との食い違いはエラーで止めます。「**ページの分け方を元に戻す**」で戻せます。
  - ※**1ページのずれは見分けられない**ので、出力前のプレビューで各枝番の先頭ページをご確認ください。
- **AIへのプロンプトを更新**しました。1つのPDFに複数の枝番が入っていないかを、
  証拠説明書 → 訴状・準備書面の引用 → 紙面の変わり目（表題・書式など）の順で確かめ、
  区切りと根拠を確認メッセージに書きます。見つけた区切りは入力欄に最初から入ります
  （**分けるのは人が確かめてから**です）。手がかりが弱いときは推測で区切らず、確認に回します。
  ※新しいプロンプトは「AI用プロンプトをコピー」で取り出せます。

### 使い勝手の改善
- **照合で問題がなければ、照合画面を飛ばして確認画面へ直接進む**ようにしました。
  読み込み忘れ・AIへの送り忘れ・証拠説明書との食い違い・AIからの注意があるときだけ照合画面で止まります。
  飛ばした後でも、画面上の「照合」を押せば中身を見られます。
  これに合わせ、読み込み画面のボタン名を「照合へ進む」から「**照合して進む**」に変えました。

### 不具合の修正
- AIが枝番を「1～2」のような範囲で返したとき、**枝番の並び順が狂う**ことがある問題を修正しました
  （「1～2」を「12」と読んでいました）。

## 4.0.0 — アプリ名を「LegalLeaves」に改称

### 名称とデザインの変更
- **アプリ名を「楽々mints」から「LegalLeaves」へ変更**しました。
  タグラインは「**e裁判の書類を、軽っと整える。**」です。
  - 「mints」は裁判所のシステム名のため、製品名に含めると**公式・提携と誤解される**おそれがありました。
  - 「楽々」は他社の既存製品群と紛らわしいため避けました。
  - ※**機能の説明としての「mints」への言及は残しています**（何のためのソフトかを示すために必要なため）。
    将来のTreeeS移行も見据え、出力フォルダ名は「**提出用ファイル**」に変えました（旧「mints提出用ファイル」）。
- **アイコンを変更**しました（葉と「L」を組み合わせたもの）。
- **ブランド名の書体を明朝（Noto Serif JP SemiBold）**にし、「Legal」と「Leaves」を色で分けました
  （Legal=#2E4D39／Leaves=#4F8F3A）。フォントは必要な文字だけに絞って同梱しているため、
  **オフラインでも同じ見た目**になります（外部通信は従来どおりゼロ）。
- **exeのファイル名が `LegalLeaves.exe` に変わりました**（旧 `楽々mints.exe`）。
- **画面の配色をブランドの緑に変更**しました。主要ボタン・見出しは深緑（#2E4D39）です。
  「確認済み（緑）」「要確認（橙）」などの**状態の色は今までどおり**で、意味は変わりません。
  ※選択中の行だけは中立の淡い灰にしました（緑にすると「確認済み」と見分けがつかなくなるため）。

### 不具合の修正
- **「編集をすべて取り消す」のあと、種類などの選択が反応しなくなる問題を修正**しました
  （他のソフトへ切り替えないと直らない状態になっていました）。確認のダイアログを
  Windows標準のものに置き換え、閉じたあと必ずアプリへ戻るようにしています。
- **種類を「証拠」から「主張系」などに変えても証拠のままだった問題を修正**しました。
  証拠でなくなったときは証拠番号と押印も外れ、一覧からも外れます。

### 引き継ぎについて（ご確認ください）
- 名称変更にともない**設定の保存先が変わります**が、**事務所の書き方メモ・最近使ったフォルダ・設定は
  初回起動時に自動で引き継がれます**（旧フォルダも消さずに残します）。
- **旧バージョンのexeは、新しいexeと入れ替えてください**（両方置いておくと保存先が分かれます）。

## 3.10.0 — v3.9.0実機テストのフィードバック一括対応（第2弾の残件実装）

### 配布ファイルの真正性確認（SEC-A7）
- **ビルド時にSHA-256のハッシュ値を自動生成**するようにした。本ソフトは無料のため有料の
  コード署名証明書は使わないが、代わりに受け取った方が **`Get-FileHash` で「配布時から中身が
  変わっていないか」を自分で確認できる**ようにしたもの。`dist/楽々mints.exe.sha256.txt`
  （zip配布なら `dist/楽々mints-v*.zip.sha256.txt`）に、確認手順つきで書き出される。
  **この控えは本体とは別の経路（メール本文など）でお伝えください**（同じ場所に置くだけでは、
  両方を差し替えられたときに検知できないため、zipの中にも入れていません）。
- 同梱の「はじめにお読みください.txt」も、警告が出る理由の説明と**ハッシュ値の照合手順**を
  先に案内する内容に改めた（従来は警告を読み飛ばす手順だけを書いていた）。

### 安全な操作・ドキュメント
- **「アプリのデータを完全に削除」に確認ダイアログを追加（SEC-A6）**: 取り消せない操作なのに、
  確認が画面側だけだった。**削除される実際のフォルダのパスと内訳を示すWindowsの確認ダイアログ**を
  出すようにし、既定を「キャンセル」にした（画面側の二重確認は廃止して1回に）。
- **README・配布文書を最新化**: READMEがこのアプリの説明になっていなかったため書き直し。

### PDFに潜む要素のお知らせ（SEC-C13）
- **PDF内のJavaScript・埋め込みファイル・入力フォームなどを検出して確認画面に表示**するようにした。

  あります**。楽々mintsは**削除しません**（証拠の内容を変えないため）。含まれている場合は

### 表示の正確さ
- **「メタデータを完全削除」の表現を実装に合わせて修正（SEC-A5）**: 実際に削除しているのは
  タイトル・作成者・件名・キーワード・作成アプリ・出力アプリとXMPで、作成日時やPDF内の
  JavaScript・添付などは対象外のため、「完全削除」は過大な表現だった。
  **「事務所名・個人名が入りうるメタデータを削除」**に改め、ヘルプに**削除される項目と
  対象外の項目を明記**した（本文に書かれた氏名・事務所名は消えないことも明示）。

### 出力の安全性
- **出力が途中で失敗しても壊れたファイルを残さない（SEC-A4）**: これまでは提出用のファイル名へ
  直接書き込んでいたため、ディスクの空き不足やクラッシュが起きると「途中まで書かれたPDF」が
  提出用の名前で残る恐れがあった。**一時ファイルに書き切ってから最終的な名前に変える**方式に変更し、
  失敗した場合は最終的なファイル名が作られないようにした（PDF・証拠説明書・音声動画のコピーすべて）。

### 配布ファイルの軽量化
- **アプリのサイズを大幅に削減（SEC-B1）**: プレビュー表示に使うPDF部品（PDF.js）が、実際に使う
  約1.7MBのファイルとは別に、**部品一式（未使用のWindows用バイナリを含む）まで配布物に入っていた**。
  実行時には同梱済みの2ファイルしか読まないため、部品一式を開発時のみの扱いに変更した。
  結果、**アプリ本体 69.2MB → 35.3MB／exe 107.5MB → 95.5MB**（約12MB小さく、起動時の展開や
  ウイルススキャンの負荷も軽くなる）。**動作・表示は一切変わりません**。

### 安全性の強化（外部AIの出力・細工されたPDFへの備え）
- **AIの整理データ(JSON)の検証を強化（SEC-A1）**: これまでは「JSONとして読めること」しか確認して
  いなかったため、壊れたデータや極端に大きなデータで画面が固まる・強制終了することがあり得た。
  ファイル件数・押印指示の件数・文字数・ページ番号に上限を設け、問題があれば**進む前に分かりやすい
  メッセージ**で知らせるようにした（上限は実務の最大想定より十分大きく、通常の利用では出ない）。
- **証拠説明書の番号範囲の突き合わせを保護（SEC-A2）**: AIが「甲1〜甲999999999」のような異常な範囲を
  出しても固まらないよう、範囲が広すぎる場合は突き合わせをスキップして案内するようにした。
- **細工されたPDFでのメモリ枯渇を防止（SEC-A3）**: プレビュー用の白黒スキャン変換に、1画像あたり・
  1ファイル合計の画素数上限を設けた。上限を超える画像は変換せず、従来どおり「プレビューでは表示
  できません」の注記が出る（**出力ファイルには一切影響しません**）。
- **自動テストを追加**: `npm test` で上記の検証と、白黒スキャン変換の正しさ（復元した画像が元と一致
  するか）を自動確認できるようにした。

  種類を証拠にしたとき、既存の採番から次番号が分かれば自動で振り（すぐ並べ替え・押印できる）、

  null（＝電磁的記録）とし、それだけを理由に要確認を出さないようにした（mints提出は通常データ提出で
  記載なしで足りるため）。
- **ファイル名の号証番号をAIが優先して読むように（プロンプト）**: ファイル名に号証番号が入っている
  とき（例「弁3-3.pdf」「甲003_契約書.pdf」）、AIが勝手に通し番号を振り直さず、その番号・枝番を
  そのまま採用するよう明記（「弁3-3」→ 弁003の枝番3。従来は 弁004・枝番なし等になることがあった）。

  既知の号証記号（甲乙丙…弁検、系列の甲A等）＋番号のときは、AIの値に依らずその番号・枝番を採用する

  ファイル添付時にチャットへ貼ればAIがファイル名を正しく認識する。プロンプトをGem等に登録済みで毎回
  コピーしない運用でも、これだけ貼ればよい（UX-40のアプリ側確定と合わせて二重の備え）。
- **非A4/A3のPDFを自動でA4/A3に整える（UX-39）**: 名刺スキャンやレターサイズなど、A4/A3でない
  PDFがそのままのサイズで出力されていた（裁判所提出はA4/A3原則）。1ページでもA4/A3でないPDFは、
  A4/A3の紙面に整える。**名刺のように余白を残して収まる小さいものは原寸のまま・A4縦で中央配置**
  （紙印刷・ファイルしやすいように。拡大しない）。**内容に応じてA4かA3を自動選択**し、A4に収まらない
  大きな図面等はA3にして読みやすくする（A3にも収まらないものだけ縮小）。幅が用紙幅を超える幅広の
  内容は横向き。A4/A3のPDFはそのまま（不要な再変換をしない）。結合・プレビューにも反映。※当初は内容を
  再埋め込みして拡大していたが、プレビューが真っ白になる・原寸でなく拡大される不具合があり方式を変更。
  最終的に、原寸で収まるものは**内容ストリームを一切変更せずページ枠（MediaBox）だけを広げて中央に見せる**
  方式にした（スキャンPDFの画像をそのまま描くのでプレビューのpdf.jsでも確実に描画される。押印は用紙枠に
  合わせて配置）。
- **A3を超えるPDFを読み込み時に警告（UX-42）**: mintsの提出物はA4/A3のみ。A3を超えるPDF（大きな図面等）は

- **「クリップボードから貼り付け」ボタンをテキスト欄の上へ（UX-38）**: 大きなJSON貼り付け欄の

  縮小ウィンドウでも見える位置にした。
- **ドラッグで枝番にする／枝番を解除する（FB-21② Phase 3拡張）**: 一覧で証拠を別の証拠の
  中央に重ねてドロップすると、その号証の枝番として取り込まれる（甲5を甲3に重ねる→甲3の2、元の甲3は
