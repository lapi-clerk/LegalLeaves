## 走らせ方

```powershell
node test/tables.test.js            # 表と今の結果を比べる（npm test にも入っている）
node test/tables.test.js --write    # 今の結果を表の expect に書き込む
py\.venv\Scripts\python py\tests\tables_check.py   # 同じ表を Python の判定に通す（npm test にも入っている）
node test/compare-random.js         # でたらめな入力で、画面と Python を比べる（npm test には入れていない）
```

表の期待値（expect）を書くのは画面側の `--write` だけ。Python 側は比べるだけで、書き込まない。

`--write` は**判定をわざと変えたときだけ**使う。書き込んだら `git diff test/tables` を開き、
変わった結果が意図どおりかを人が確かめる。確かめずにコミットすると、表が「たまたま今そうなっている値」に
なり、正の役目を果たさなくなる。

## 表の形

### 関数の表（`"kind": "function"`）

```jsonc
{ "fn": "toFullWidth", "args": ["abc"], "expect": "ａｂｃ" }
{ "fn": "submitExtFor", "args": ["訴状.docx"], "state": { "renameOnly": true }, "expect": ".pdf" }
```

`state` を付けると、呼ぶ前に画面の状態をその値にする（`renameOnly`・`placeholders`・`mergeDisabled` など）。

### 流れの表（`"kind": "flow"`）

入力は 2 通り。

- `files`（読み込んだファイル）と `ai`（AI の整理データ。壊れた文字列を試すときは `aiText`）… 形式チェックから通す
- `reviewFiles`（確認画面の一覧）… 人が手直しした後の状態から、出力前チェックと出力の計画だけを通す

どちらも `settings` で `renameOnly`・`noAi`・`manualMatches`・`mergeDisabled`・`placeholders` を指定できる。
`expect` には、確認画面の一覧・読み込み忘れ・突き合わせ・注意・番号の食い違い・出力前チェック・出力の計画・
証拠説明書の名前とデータが入る。

### 省略の書き方

大きな入力は、表に直接書かずに次の形で書く（JS と Python の両方がこれを広げる）。

```jsonc
{ "$repeat": ["あ", 1001] }   // 「あ」を 1001 個つなげた文字列
{ "$array": [{}, 300] }       // {} を 300 個並べた配列
```

### 結果のそろえ方

結果は JSON にできる形へそろえてから比べる。値が無い項目（JS の `undefined`）は消え、
値そのものが無いときは `null` になる。**Python 側も同じそろえ方をすること**
（値が `None` の項目を残すと食い違う。JS の `null` は残る）。

## 紛らわしい 2 つの文字

「～」に見える文字は 2 つあり、目では区別できない。表の中では `\u` の形で書く（`--write` が自動でそうする）。

| 書き方 | 文字 | 扱い |
| --- | --- | --- |
| `～` | 全角チルダ | 使う（枝番の範囲 `1～2` など） |
| `〜` | 波ダッシュ | 禁止。外へ出る値（提出用ファイル名・証拠説明書）に入ってはいけない |

`no_wave_dash` に挙げた関数・項目の結果に波ダッシュが入ると、テストが落ちる。
`"known_wave_dash": true` を付けた件は「**いまは入ってしまう**」と分かっているもの（未修正の印）。
直したらテストが「印を外してください」と知らせる。いまは、この印の付いた件は無い。

波ダッシュは、外へ出る値に入る手前で全角チルダにそろえている（`fixWaveDash`）。そろえる場所は、
ファイル名にする関数・全角／半角にする関数・AI の枝番と押印の枝番を読むところ・出力の計画の名前。
画面に見せるだけの値（確認画面の標目の欄・照合画面の知らせの文）は、入力のまま残る。

## 表を作って分かったこと（2026-11-10）

### 未修正（決めていない・直していない）

表は**いまの動きをそのまま写した**ものなので、次の動きも「正」として入っている。
直すと決めたら、実装を直し、`--write` で表を書き直し、差分を確かめる。

1. **ファイル名にするときの半角化が、全角のピリオド（．）を直さない**（`Ｒ６．４．１２` → `R6．4．12`）
2. **結合する名前の標目は、1 つ目の枝番のものになる**（請求書と領収書をまとめると `甲002_1～2_請求書.pdf`）。
   中身と名前が合わないことがある。実際の AI からつないで試したとき、AI が指摘した（2026-11-12）。
   名前は変えていないが、**標目の違うファイルをまとめるときは、出力前チェックで知らせる**ようにした（2026-11-15）
3. **AI が提出用の名前（`suggested_base_name`）を書かなかった証拠は、番号の付かない名前になる**（`写真.pdf`・`録音.mp3`）。
   1 ファイルだけの号証なら、確認画面と出力前チェックが「号証番号で始まっていません」と知らせる

### 決めたこと（2026-11-12）

- **提出用ファイル名の範囲は、全角チルダ（～）のままにする。** シリーズ憲章 第7章の「ファイル名は半角チルダ（~）」のほうを直す
  （配布済みの版の動きを変えない。裁判所の資料にも表記のゆれがある）
- **「リネーム＋メタデータ削除」でも、ファイル名の先頭の号証番号は 3 桁にそろえる**（`甲1_契約書.pdf` → `甲001_契約書.pdf`）。
  今のままでよい。この使い方では、番号は押さない（名前だけが変わる）
- **ファイル名の `_` のあとの数字は、2 桁までを枝番と読む**（下の「直した」）

### 直した（2026-11-11〜15・5.5.0 に入れた）

- **AI の項目が無いファイルで、番号が二重になる** … `甲1_契約書.pdf` → `甲001_契約書.pdf`
  （以前は `甲001_甲1_契約書.pdf`）。番号だけの名前 `甲1.pdf` は `甲001.pdf`（以前は `甲001_甲1.pdf`）
- **結合する名前で、枝番の範囲がつながる** … 全部の枝番の最小と最大で作る
  （`1～2` と `3` → `甲003_1～3_写真.pdf`。重なり `1` と `1` → `甲003_1_写真.pdf`）
- **読み込み時、アプリ自身の付けた枝番を読めない** … `甲001_2_領収書.pdf` の `_2` を枝番と読む。
  `_` のあとの数字は **2 桁まで**で、直後が区切りか末尾のときだけ
  （`甲1_2024_契約書`・`甲1_2024年契約書`・`甲1_2通目`・`甲1_123_資料` は枝番にしない。
  人が付ける `甲1の123`・`甲1-123` は、桁数にかかわらず読む）
- **正しくない番号（`甲0`）が証拠説明書に出る** … 行にも、証拠説明書の名前の範囲にも入れない
  （空き枠も同じ。出力前チェックの知らせは従来どおり出る）
- **波ダッシュ（U+301C）が外へ出る値に入る** … AI や人が波ダッシュで書いた範囲（`1〜2`）を、全角チルダにそろえる。
  提出用ファイル名（`甲005_1～2_….pdf`）・押す番号の枝番・証拠説明書の号証欄と中身（標目・作成年月日など）
- **AI が枝番を書き、押印の指示を書かなかったファイルで、押す番号に枝番が入らない** … 枝番の違うファイルが
  どれも「甲第5号証」と押されていた。ファイルの枝番を、押す番号にも入れる（「甲第5号証の1」「甲第5号証の2～3」）。
  AI が押印の指示を書いたファイルは、AI の指示のまま。実際の画面での確認で見つかった
